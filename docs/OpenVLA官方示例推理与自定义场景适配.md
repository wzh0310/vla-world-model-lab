# OpenVLA 官方示例推理与自定义场景单步闭环

本文记录 OpenVLA 原生推理链路的跑通结果、7 维动作解析、性能基线，以及把模型接到本项目 PushCube 仿真场景的单步推理闭环。所有命令在 `wzh-ai` 容器内执行：模型推理走 `vla` 环境，仿真采集与执行走 `mujoco` 环境。

## 1. 官方示例单帧推理

### 输入来源

OpenVLA 官方仓库不含独立示例图，模型卡也无附带观测图。本次使用**官方项目主页**（`openvla.github.io`）teaser 图中的 Bridge 机器人相机观测，裁出单帧画面并缩放为 224×224，保存为 `results/openvla_official_demo.jpg`。指令取自主页列出的官方任务示例：`put the yellow corn on the plate`。

prompt 严格按官方模板构造：

```
In: What action should the robot take to put the yellow corn on the plate?
Out:
```

### 输出解析

`predict_action` 的返回值已按 `unnorm_key="bridge_orig"` 反归一化，是 7 维**真实物理增量**，不是 [-1,1] 归一化值。要恢复模型输出的归一化 token 中心，需用同一数据集的 q01/q99 反算：`norm = 2*(raw - q01)/(q99 - q01) - 1`。

| 维度 | 含义 | 反归一化输出 | 归一化值 |
|---|---|---:|---:|
| 0 | dx（x 方向位移） | -0.00916 | -0.31373 |
| 1 | dy（y 方向位移） | -0.00107 | -0.01569 |
| 2 | dz（z 方向位移） | -0.00154 | -0.25882 |
| 3 | drx（x 轴旋转） | -0.01099 | -0.14118 |
| 4 | dry（y 轴旋转） | -0.00279 | 0.05490 |
| 5 | drz（z 轴旋转） | 0.01766 | 0.09412 |
| 6 | gripper（夹爪） | 0.99608 | 0.99216 |

输出符合预期：7 维数值均在 Bridge 数据集 q01/q99 范围内，夹爪接近 1（闭合）。完整结果见 `results/openvla_official_demo_inference.json`。

### 性能基线（A6000 48GB，bf16，batch=1）

| 指标 | 数值 |
|---|---|
| 单帧推理均值 | 0.2738 s |
| 标准差 / 最小 / 最大 | 0.0012 / 0.2720 / 0.2754 s |
| 等效控制频率 | 3.65 Hz |
| 显存分配 / 保留 | 15.139 / 15.532 GB |
| 权重加载耗时 | 约 11–12 s（3 个 safetensors 分片） |

3.65 Hz 低于 BridgeData V2 采集时的 5 Hz 非阻塞控制频率，说明 bf16 全精度推理在这张卡上接近实时但仍有延迟压力。结合此前的 int4 实测（显存 4.38/4.55 GB、单步 1.31 s），**显存可以压到 8GB 以内但吞吐下降明显**；这是量化部署时必须一起权衡的指标。

硬件可行性结论：A6000 48GB 跑 bf16 推理与 QLoRA 微调都可行；若按论文默认 batch=16 全量微调需约 60GB 以上，应减小 batch 并用梯度累积。

## 2. PushCube 自定义场景单步闭环

### 三段式管线（保持环境隔离）

```bash
MUJOCO=/opt/miniconda3/envs/mujoco/bin/python
VLA=/opt/miniconda3/envs/vla/bin/python
R=/data/wzh/robot/vla-world-model-lab

# 1) mujoco：截取 top_cam 224×224 观测 + 保存可复现初始状态
$MUJOCO $R/scripts/capture_pushcube_for_vla.py

# 2) vla：英文指令推理 + 动作空间映射
$VLA $R/scripts/infer_vla_action_for_mujoco.py

# 3) mujoco：恢复同一状态，执行一步并保存前后对比图
$MUJOCO $R/scripts/apply_vla_action_to_mujoco.py
```

### 动作空间映射（核心适配点）

OpenVLA 输出是 Bridge WidowX 的 7 维末端增量；PushCube 只接受 4 维 `[dx, dy, dz, gripper]`，位移上限 ±0.02 m。映射分三步：

1. 丢弃旋转三维 `drx/dry/drz`（推物任务不需要末端旋转）；
2. 用 `bridge_orig` 的 q01/q99 把反归一化输出还原到 [-1,1]，避免把 Bridge 的物理增量直接当成本环境的米数；
3. `xyz = norm[:3] × 0.02`，夹爪 `g = (norm[6]+1)/2` 映射到 [0,1]。该位在 PushCube 中是保留接口，不参与动力学。

这是一条**跨本体启发式映射**，不是物理标定：两套机器人的坐标系、工作空间与控制器都不同，映射只保证量纲和范围一致。

### 单步结果

观测：红色目标在立方体正 x 方向 0.20 m 处，指令 `push the cube to the red target`。

| 项目 | 数值 |
|---|---|
| 原始 7 维 | [0.00941, -0.04025, -0.00778, -0.00397, -0.00413, -0.05648, 0.0] |
| 归一化 7 维 | [0.33725, -0.96471, -0.44706, -0.05490, 0.03922, -0.26667, -1.0] |
| 映射后 4 维 | [0.00675, -0.01929, -0.00894, 0.0] |
| EE 实际位移 | [0.0120, -0.019294, -0.008941] m |
| 立方体位移 | [0.0, 0.0] m |
| 目标距离 | 0.2000 → 0.2000 m |
| 单步奖励 | -0.065672 |

闭环成立：映射动作被环境接受并驱动末端按指令方向运动（x 正向、y 负向、z 向下），第三人称与主观相机前后帧已保存于 `results/vla_single_step/`。但必须如实说明两点：

- **方向仅部分符合预期**：目标与立方体 y 坐标相同，理想 y 位移应接近 0，模型给出了明显负 y 分量；x 正向分量方向正确。零样本跨本体迁移没有语义保证。
- **立方体未移动**：初始时末端离立方体约半米，单步最大 2 cm 不可能接触。这是单步闭环验证，不是任务成功率验证；要评估推物效果需要微调后跑多步回合。

## 3. 已知限制

- OpenVLA 只吃单张 224×224 图像，不支持本体状态、历史观测或多相机；模型未见过的仿真域需微调。
- 官方动作输出是单步、非 chunk，7 个 token 自回归生成，控制频率受限。
- 当前映射固定缩放系数 0.02 m，未做坐标系对齐或标定；后续微调时应让模型直接学习本环境动作分布。
