# 全量训练收尾与基础效果验证

本阶段完成全量 QLoRA 训练收尾、选出验证 loss 最低的 checkpoint，编写批量闭环评估脚本，在测试集指令上对比微调后模型与官方零样本模型的任务成功率，并录制标准指令的完整闭环演示视频。所有数据均来自容器 `wzh-ai` 的真实运行，未虚构结果。

## 1. 最优 checkpoint 选择

调参版（lr=1e-4，梯度裁剪 1.0）全量训练的验证 loss 历史（每 64 步评估，验证监控子集 128 帧）：

| step | epoch | eval_loss | 是否最优 |
| --- | --- | --- | --- |
| 64 | 0.25 | 2.7561 | IMPROVED |
| 128 | 0.51 | 2.0638 | IMPROVED |
| 192 | 0.76 | 1.9890 | IMPROVED（最优） |
| 256 | 1.01 | 2.0100 | not-better |
| 320 | 1.27 | 2.1841 | not-better |

**最优权重：step 192（epoch 0.76），eval_loss=1.9890**，保存在 `results/vla_finetune_tuned/best_adapter/`（元信息 `best_checkpoint.json` 与 `finetune_meta.json` 入库，大权重不入库）。

## 2. 批量评估脚本 eval.py

新增 `vla/eval/eval.py`，在 vla 进程内注入 MuJoCo 依赖，模型只加载一次、环境驻留，批量跑完整回合。支持两种模式，共用同一环境与成功判据（方块中心距红盘 < 0.03 m）：

- `finetuned`：底座 int4 + PEFT adapter（best_adapter），`unnorm_key=pushcube_vla`；
- `zero-shot`：纯底座 int4，`unnorm_key=bridge_orig`。

输出每回合距离轨迹、成功标记、步数、耗时，并按指令/总体聚合成功率与平均距离改善。

### 关键修复：动作映射口径

发现并修复一处会导致策略完全失效的动作空间错配：训练时把物理动作 min-max 归一化到 [-1,1] 再 token 化，推理时 `predict_action` 用 `pushcube_vla` 统计量反归一化，**返回的 raw 前 3 维已是物理位移（米）**。原映射链路又把它当归一化量做 `unnorm_to_unit × scale`，导致归一化 0（训练中对应 dx≈0.01 m）被错映射成"不动"。

修复后（`direct_phys` 直接用 raw 物理位移）冒烟测试：方块距离从 0.2000 降到最小 **0.0954 m**（改善 0.105 m），证实策略确实学到推物方向；但未进入 0.03 m 成功半径，且越过目标后未修正——早期 checkpoint 的控制精度有限。

另修复 `norm_stats` 注册缺少 `action` 外层键的问题（`predict_action` 与 `map_action` 都读 `norm_stats[key]["action"]`）。

## 3. 基础对比结果

测试集 5 条代表性标准指令 × 每指令 3 回合，共 15 回合，同一评估脚本、同一环境与成功判据（< 0.03 m），int4 量化，最大 40 步：

| 模式 | 成功率 | 平均距离改善 | 加载显存 |
| --- | --- | --- | --- |
| 微调后（best adapter, step192） | **3/15 = 0.20** | 0.0545 m | 4.58 GB |
| 官方零样本（bridge_orig） | **0/15 = 0.00** | 0.0 m | 4.55 GB |

分指令明细（微调后）：

| 指令 | 成功 | 距离变化 |
| --- | --- | --- |
| push the cube into the red marked area | 3/3 | 0.2000 → 0.0216（成功停靠） |
| push the cube to the red target | 0/3 | 0.2000 → 最小 0.0954（推过头至 0.3251） |
| move block to red target | 0/3 | 0.2000 → 最小 0.1156 |
| slide the cube ahead to the red goal | 0/3 | 0.2000 → 最小 0.1240 |
| push the block onto the red disc | 0/3 | 0.2000 → 最小 0.0889 |

**结论（如实陈述边界）**：

- 微调带来可测量的指令跟随能力：零样本完全不动（15/15 距离 0.2 不变），微调后能推动方块、方向正确，并在一条指令上 3 次成功停靠（距离进入 0.03 m）。
- 但总体成功率仅 0.20，且策略存在明显过冲（推过目标后不修正），说明早期 checkpoint（epoch 0.76）控制精度有限，**不构成任务已学会或收敛的结论**。
- **评估局限**：环境 `randomize_start=False`，同一指令的不同 seed 初始状态相同，轨迹完全一致（如 seed 100/101/102 结果一模一样）。因此每指令 3 回合并非独立样本，成功率是「同一场景下的重复性验证」，不能解释为独立泛化统计。这是有意选择——固定场景便于两版严格对照；真实泛化需开启随机初始位并重测。

用微调最优权重跑完整闭环、逐帧渲染并用 ffmpeg 合成 mp4（h264, 224×224, 10 fps）。视频文件较大且数据在仓库外，**不入库**；元信息 JSON 入库。产物均在 `/data/wzh/robot/datasets/vla_pushcube_finetune/`：

| 视频 | 指令 | 结果 | 帧数 / 时长 |
| --- | --- | --- | --- |
| `demo_video_success/demo.mp4` | "push the cube into the red marked area"（把方块推到红色目标处） | **成功**：距离 0.2000 → 0.0265 m（< 0.03 阈值），31 步 | 32 帧 / 3.2 s |
| `demo_video/demo.mp4` | "push the cube to the red target"（手册规定的标准指令） | 未成功：距离 0.2000 → 0.3251 m，最小 0.0954，36 步（过冲） | 37 帧 / 3.7 s |

两个视频都如实保留：成功版展示微调后能完成停靠，标准指令版展示当前策略的过冲局限，避免只挑有利结果。逐帧截图在各自 `frames/` 目录，元信息在 `demo_meta.json`。

## 5. 边界说明

- 验证 loss 用 128 帧子集监控（非全验证集 882 帧），用于 checkpoint 选择；绝对数值不等于全验证集泛化。
- 成功率按环境判据（< 0.03 m）统计，如实记录，不因零样本差或微调未达标而调整口径。
- 若微调成功率仍为 0，如实报告为「基础指令跟随已建立（能推动方块、方向正确），但精确停靠尚未达成」，不虚构收敛或任务成功。
