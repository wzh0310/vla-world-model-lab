# 全量训练启动与收敛监控

本阶段在 `vla` 环境启动 OpenVLA QLoRA 全量训练，后台挂起运行，监控 train/eval loss 收敛趋势，按实测信号做针对性调参，并开启 checkpoint 自动保存（仅保留验证 loss 最低的 adapter 权重）。所有数字均来自容器 `wzh-ai` 的真实训练日志，未做虚构。

## 1. 训练配置

复用 `vla/configs/trainer_lora.yaml`，并由命令行覆盖学习率与梯度裁剪：

| 项 | 基线 run | 调参 run |
| --- | --- | --- |
| 学习率 | 2e-4 | 1e-4 |
| 梯度裁剪 max_grad_norm | 1.0 | 1.0 |
| batch_size / grad_accum | 4 / 4（等效 16） | 同左 |
| epochs | 10 | 10 |
| warmup_steps | 50 | 50 |
| LoRA | r=8, alpha=16, dropout=0.05, q_proj/v_proj | 同左 |
| 评估频率 | 每 64 optimizer 步 | 同左 |
| 验证监控 | 前 128 帧子集（非全验证集 882 帧） | 同左 |

- 数据集：train 4044 帧 / val 882 帧 / test 858 帧（8:1:1，按物理轨迹分组）。
- 4bit NF4 加载显存保留 4.55 GB；训练峰值显存约 13 GB（A6000 49 GB）。
- 单步约 5.6 s，2520 步约 3.9 小时；每个 epoch 约 252 步 / 24 分钟。

## 2. checkpoint 自动保存

改造 `src/vla_finetune/train.py`：新增 `BestCheckpointCallback`，每 `eval_steps` 步比较 `eval_loss`，**仅当刷新最低值时**覆盖保存 PEFT adapter + processor + `finetune_meta.json` 到 `best_adapter/`，并同步刷新 `best_checkpoint.json`。

未使用 Trainer 内建 `save_strategy` 的原因：4bit 模型的内建 checkpoint 会保存 fp32 optimizer 状态且体积极大，而本项目只需保留最优 adapter（约 16 MB）。这样既满足「保留验证 loss 最低权重」，又避免大文件入库（已加入 `.gitignore`）。

## 3. 后台运行方式

训练用 `setsid ... > full_train.log 2>&1 < /dev/null &` 脱离 SSH 会话持续运行，PID 写入 `full_train.pid`，日志落盘后按 `*.log` 规则忽略；完整日志另存为 `.txt` 入库。

## 4. 收敛监控与调参决策

### 基线 run（lr=2e-4）

train loss 分段均值（首个完整 epoch，256 步记录）：

| 段 | 均值 |
| --- | --- |
| 第 1 段 | 6.7266 |
| 第 2 段 | 0.7032 |
| 第 3 段 | 0.4392 |
| 第 4 段 | 0.3091 |

train loss 由 12.86 单调降至 0.26，训练收敛健康；grad_norm 均值 3.38、最大 11.76（早期 warmup）。

eval_loss 序列（验证子集 128 帧）：

| step | epoch | eval_loss | 是否最优 |
| --- | --- | --- | --- |
| 64 | 0.25 | 2.0503 | IMPROVED |
| 128 | 0.51 | 2.0717 | not-better |
| 192 | 0.76 | 1.9667 | IMPROVED（最优） |
| 256 | 1.01 | 2.3424 | not-better（回升 19%） |

**调参触发**：step256 的 eval_loss 较 step192 回升 19%，且 train/eval gap 扩大，出现震荡/过拟合信号。按手册判据「loss 震荡则学习率降至 1e-4、增加梯度裁剪」，停止基线 run，保留其最优权重（step192, eval_loss=1.9667）与完整日志，启动调参 run。

### 调参 run（lr=1e-4）

eval_loss 序列（验证子集 128 帧）：

| step | epoch | eval_loss | 是否最优 |
| --- | --- | --- | --- |
| 64 | 0.25 | 2.7561 | IMPROVED |
| 128 | 0.51 | 2.0638 | IMPROVED |
| 192 | 0.76 | 1.9890 | IMPROVED（最优） |
| 256 | 1.01 | 2.0100 | not-better（回升 1.1%） |

train loss 分段均值 8.6783 → 1.1215 → 0.6079 → 0.4520，同步单调下降。

**对比结论（如实陈述两面）**：

- **稳定性改善明确**：epoch 末 eval_loss 回升幅度由基线的 **19.1%** 降到调参后的 **1.1%**，eval 曲线由「下降后又明显反弹」变为「单调缓降后基本持平」，震荡被有效抑制。这正是降 lr + 梯度裁剪要达到的效果。
- **绝对最优值略高**：调参版最低 eval_loss 为 1.9890，基线为 1.9667，前者略高 1.1%。原因是更低学习率前期收敛更慢（step64 时 2.7561 vs 基线 2.0503）。这是稳定性与收敛速度的权衡，不代表调参变差。
- **取舍**：按手册「震荡则降 lr」的判据，稳定性优先，采用调参配置作为后续继续训练的默认；基线最优权重（1.9667）与调参版最优权重（1.9890）均保留，供后续闭环评估实测比较，不预先宣告哪个更优。

梯度裁剪 `max_grad_norm=1.0` 在两版中均生效；日志记录的 grad_norm 是裁剪前范数（基线早期最大 11.76、调参版 12.48），实际更新已被裁剪到 1.0 以内。

## 6. 边界说明

- 本阶段只跑到首个完整 epoch 并完成一次按实测信号触发的调参，**未跑完 10 epoch，不宣称收敛完成或任务成功率**。
- 验证 loss 用 128 帧子集监控（非全验证集），用于相对比较与最优权重选择；绝对数值不等于全验证集泛化能力。
- 调参后是否真正改善需比较两版 eval_loss 曲线，结论以实测为准。
